# BSPK Developers Portal

Mintlify-powered documentation for BSPK's public APIs.

## Development

Install the [Mintlify CLI](https://www.npmjs.com/package/mintlify):

```
npm i -g mintlify
```

Preview locally:

```
mintlify dev
```

## Regenerating API Reference Docs

When the OpenAPI specs change in the main `bspk-web-app` repo, regenerate the docs:

### 1. Generate public JSON specs

From the `bspk-web-app` repo root:

```bash
ruby scripts/openapi_strip_internal.rb
```

This reads `openapi/*.yaml`, strips endpoints and schemas marked `x-internal: true`, and writes public JSON files to `openapi/public/`.

### 2. Copy JSON specs to this repo

```bash
cp openapi/public/platform_v1.json ~/Projects/bspk/docs/api-reference/platform_v1.json
cp openapi/public/extraction_v1.json ~/Projects/bspk/docs/api-reference/extraction_v1.json
```

### 3. Regenerate endpoint MDX files

From this repo root (`~/Projects/bspk/docs`):

```bash
# Remove old generated endpoint files
rm -rf api-reference/platform-api/endpoints/clients
rm -rf api-reference/platform-api/endpoints/shoppers
rm -rf api-reference/platform-api/endpoints/shopper-metafields
rm -rf api-reference/platform-api/endpoints/products
rm -rf api-reference/extraction-api/endpoints

# Regenerate
npx @mintlify/scraping@latest openapi-file api-reference/platform_v1.json -o api-reference/platform-api/endpoints
npx @mintlify/scraping@latest openapi-file api-reference/extraction_v1.json -o api-reference/extraction-api/endpoints
```

### 4. Update navigation

The scraping tool outputs a `navigation object suggestion`. If endpoint slugs changed, update the page references in `docs.json` to match.

**Note:** Hand-written pages (e.g. `webhooks/introduction.mdx`, `webhooks/events-and-payloads.mdx`) are not generated by the scraping tool — do not delete them.

## Publishing Changes

Push to the default branch. The Mintlify GitHub App auto-deploys to production.

### Troubleshooting

- `mintlify dev` not running — run `mintlify install` to re-install dependencies
- 404 on a page — check that the page path in `docs.json` matches an existing `.mdx` file
